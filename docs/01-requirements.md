# Requirements — โปรแกรมให้คะแนนการแข่งขัน (score-app)

> ชื่อโปรแกรม: ชั่วคราวใช้ `score-app` (จะเปลี่ยนภายหลัง)
> เอกสารฉบับร่าง v0.1 — 2026-09-29

## 1. 📋 ภาพรวม (Overview)

ระบบเว็บสำหรับให้คะแนนการแข่งขัน โดยมีกรรมการหลายคนให้คะแนนแยกกัน (มองไม่เห็นคะแนนของกันและกัน)
แล้วระบบนำคะแนนมารวม คำนวณถ่วงน้ำหนักตามหัวข้อ และจัดอันดับผู้เข้าแข่งขัน

ระบบแบ่งเป็น 2 ฝั่งหลัก:
- **ฝั่ง Admin (หลังบ้าน)** — ตั้งค่าการแข่งขัน หัวข้อ น้ำหนัก ผู้เข้าแข่งขัน กรรมการ และดูผล/จัดอันดับ
- **ฝั่งกรรมการ (หน้าบ้าน)** — กรรมการแต่ละคนเข้าผ่านลิงก์เฉพาะของตน กรอกคะแนนแยกกัน

## 2. 👥 ผู้ใช้งาน (Actors)

| Actor | คำอธิบาย |
|-------|----------|
| Admin | ผู้จัดการแข่งขัน สร้าง/ตั้งค่าการแข่งขัน แจกลิงก์กรรมการ ดูผลและจัดอันดับ |
| Judge (กรรมการ) | เข้าผ่านลิงก์เฉพาะ กรอกคะแนนของผู้เข้าแข่งขันแต่ละราย ไม่เห็นคะแนนกรรมการคนอื่น |

## 3. ⚙️ Functional Requirements

> **สถานะการทำ (v0.2.0):**

> - [x] กรรมการกรอกคะแนนผ่านลิงก์ · ความเป็นส่วนตัว (FR-7..12)
> - [x] คำนวณถ่วงน้ำหนัก + เฉลี่ย + จัดอันดับ (FR-13..17)

> - [x] หลายการแข่งขัน + ค้นหา/กรอง + Lock/Unlock + ลบ (FR-20..23)
> - [x] แสดงเวอร์ชันบนเว็บ (FR-24)

### 3.1 การจัดการการแข่งขัน (Admin)
- **FR-1** Admin สร้างการแข่งขันใหม่ ระบุชื่อการแข่งขัน วันที่ และคำอธิบาย
- **FR-2** Admin กำหนด **จำนวนกรรมการ** และสร้างรายชื่อกรรมการ (ชื่อ/ป้ายกำกับ เช่น "กรรมการ 1")
- **FR-3** Admin กำหนด **หัวข้อการให้คะแนน** ได้หลายหัวข้อ แต่ละหัวข้อมี:
  - ชื่อหัวข้อ
  - น้ำหนัก (%) — ผลรวมของทุกหัวข้อต้องเท่ากับ 100%
  - ช่วงคะแนน: คงที่ 0–5 ต่อหัวข้อ เป็นจำนวนเต็ม (0, 1, 2, 3, 4, 5)
- **FR-4** Admin จัดการรายชื่อผู้เข้าแข่งขัน (competitor) — **เพิ่ม/ลด/แก้ไขได้** ทั้งก่อนและระหว่างแข่ง
  - ผู้เข้าแข่งขันนับเป็น **1 หน่วย (entry)** ไม่ว่าจะเป็นบุคคลเดียวหรือทีม (ไม่สนจำนวนคนในทีม)
  - แต่ละ entry มี: ชื่อ/ชื่อทีม, หมายเลข (bib/order), หมายเหตุ (optional), ลิงก์ผลงาน (optional — ดู FR-25)
- **FR-5** Admin เปลี่ยนสถานะการแข่งขัน: `draft` → `open` (เปิดให้กรรมการกรอก) → `closed` (ปิด รวมผล)
- **FR-6** Admin สร้าง/เพิกถอน **ลิงก์เฉพาะสำหรับกรรมการแต่ละคน** (access link พร้อม token) เพื่อแจกให้กรรมการ
- **FR-25** Admin แนบ **ลิงก์ผลงาน (URL) ให้ผู้เข้าแข่งขันแต่ละราย** ได้ (1 ลิงก์/entry, optional) เพื่อใช้แสดงผลงานของทีม
  - 🆕 **วางแผนทำในเวอร์ชันใหม่ (พร้อมการย้ายขึ้น AWS — ดู `08`/`10`)** ยังไม่อยู่ในของเดิม
  - **เฉพาะ Admin เป็นผู้แนบ/แก้ไข** (กรรมการแนบไม่ได้)
  - ระบบแสดงลิงก์เป็น **ปุ่มเปิดลิงก์** (เปิดแท็บใหม่) ไม่ต้อง embed/preview
  - ตรวจรูปแบบ URL เบื้องต้น (ขึ้นต้น `http://`/`https://`) — ว่างได้ (ไม่บังคับ)

### 3.2 การให้คะแนน (Judge)
- **FR-7** กรรมการเข้าระบบผ่านลิงก์เฉพาะของตน โดยไม่ต้องสมัครบัญชี (token ในลิงก์ผูกกับกรรมการ + การแข่งขัน)
- **FR-8** กรรมการเห็นรายชื่อผู้เข้าแข่งขันทั้งหมดของการแข่งขันนั้น และสถานะว่าให้คะแนนครบหรือยัง
- **FR-9** กรรมการกรอกคะแนนแต่ละหัวข้อ (0–5) สำหรับผู้เข้าแข่งขันแต่ละราย
- **FR-10** กรรมการ **มองไม่เห็นคะแนนของกรรมการคนอื่น** และมองไม่เห็นคะแนนรวม/อันดับ
- **FR-11** กรรมการแก้ไขคะแนนของตนได้จนกว่าจะกด "ส่งคะแนนทีมนี้" (ล็อก) — admin ปลดล็อกให้แก้ได้ (ดู §3.5)
- **FR-12** ระบบบันทึกคะแนนอัตโนมัติ (auto-save) และแสดงสถานะความคืบหน้าของกรรมการเอง

### 3.3 การนำเสนอสดหน้างาน (Live Presentation) — รายละเอียดใน `04-live-workflow.md`
- **FR-L1** การแข่งเป็นแบบ present สดทีละทีม; Admin ควบคุมคิวว่า "ทีมใดกำลัง present" และหน้าจอกรรมการ sync ตาม
- **FR-L2** กรรมการกด "ส่งคะแนนทีมนี้" เพื่อล็อกคะแนนของทีมนั้น (สถานะ SUBMITTED); Admin ปลดล็อกให้แก้ได้
- **FR-L3** Admin มี **Live Dashboard** เห็นสถานะสด (กรรมการ×ทีม: ยังไม่เริ่ม/กรอกบางส่วน/ส่งครบ) และตัวนับความครบถ้วน โดย **ไม่แสดงตัวเลขคะแนน/อันดับระหว่างแข่ง**
- **FR-L4** สถานะบน Dashboard อัปเดตแบบ real-time เมื่อกรรมการเปลี่ยนสถานะ

### 3.4 การรวมผลและจัดอันดับ (Admin)
- **FR-13** ระบบคำนวณคะแนนของกรรมการแต่ละคนต่อผู้เข้าแข่งขัน = ผลรวมถ่วงน้ำหนัก (Σ คะแนนหัวข้อ × น้ำหนัก%) → เต็ม 5
- **FR-14** ระบบคำนวณคะแนนสุดท้ายของผู้เข้าแข่งขัน = ค่าเฉลี่ยคะแนนจากกรรมการทุกคน (เต็ม 5)
- **FR-15** Admin ดูผลได้หลังปิดการแข่งขัน (default) — เห็นตารางที่แสดง:
  - คะแนนที่กรรมการแต่ละคนให้ในแต่ละหัวข้อ (breakdown ต่อกรรมการ/ต่อหัวข้อ)
  - คะแนนรวมต่อกรรมการ
  - คะแนนสุดท้าย (เฉลี่ย) และอันดับ
- **FR-16** ระบบจัดอันดับผู้เข้าแข่งขันจากคะแนนสุดท้าย (มากไปน้อย) พร้อมจัดการกรณีคะแนนเสมอ (tie-break)
- **FR-17** Admin ตรวจสอบความครบถ้วนได้ว่ากรรมการคนใดยังให้คะแนนไม่ครบ ก่อนปิดการแข่งขัน

### 3.5 รายงาน / Export / Import
- **FR-18** Admin export ผลการแข่งขันเป็นไฟล์ Excel (.xlsx) — มีชีตสรุปผล+อันดับ, ชีตคะแนนรายกรรมการ (Total เป็นสูตร), หัวข้อ, ผู้เข้าแข่งขัน, ข้อมูล *(ทำแล้ว v0.2.0)*
- **FR-19** Admin import ไฟล์ Excel ที่ export จากระบบ → สร้างเป็น **การแข่งขันใหม่** (ไม่เขียนทับของเดิม; ลิงก์กรรมการถูกสร้างใหม่) *(ทำแล้ว v0.2.0)*
  - import อยู่เฉพาะฝั่ง Admin เท่านั้น
  - ไฟล์เสีย/ผิดรูปแบบ → แจ้ง error ไม่สร้างข้อมูลค้าง (ทำใน transaction เดียว)
  - PDF: ยังไม่ทำ (อนาคต)

### 3.6 การจัดการหลายการแข่งขัน (Admin) *(v0.2.0)*
- **FR-20** Admin ดูรายการการแข่งขันทั้งหมดเป็นตาราง พร้อม **ค้นหาชื่อ** และ **กรองตามสถานะ** (draft/open/closed)
- **FR-21** Lock/Unlock: ปิดรับคะแนน (open → closed) และปลดล็อกกลับมาแก้ได้ (closed → open) กันกดผิด
- **FR-22** ลบการแข่งขันได้ **เฉพาะเมื่อ locked (closed)** เท่านั้น — ลบคะแนน/ผู้เข้าแข่ง/กรรมการทั้งหมดตาม (cascade); ควร export เก็บก่อนลบ
- **FR-23** Admin เพิ่ม/ลบกรรมการได้; ซ่อน/แสดงลิงก์กรรมการแต่ละคน (toggle)

### 3.7 เวอร์ชัน *(v0.2.0)*
- **FR-24** แสดงเลขเวอร์ชันแอปบนหน้าเว็บ (มุมล่างขวา) ดึงจาก `GET /api/version`

## 4. 🔒 Non-Functional Requirements

- **NFR-1 ความเป็นส่วนตัวของคะแนน** — กรรมการต้องไม่สามารถเข้าถึงคะแนนของกรรมการคนอื่นได้ ทั้งผ่าน UI และ API
- **NFR-2 ความปลอดภัยลิงก์** — token ของกรรมการต้องเดายาก (สุ่มความยาวพอ) เพิกถอน/สร้างใหม่ได้
- **NFR-3 การใช้งานพร้อมกัน** — รองรับกรรมการหลายคนกรอกคะแนนพร้อมกันได้โดยข้อมูลไม่ชนกัน
- **NFR-4 ความถูกต้องของข้อมูล** — ตรวจสอบ input (คะแนนอยู่ในช่วง 0–5, น้ำหนักรวม = 100%) ทั้งฝั่ง client และ server
- **NFR-5 ความคงทน** — auto-save กันคะแนนหายกรณีปิดเบราว์เซอร์/เน็ตหลุด
- **NFR-6 การใช้งานง่าย** — หน้ากรรมการต้องเรียบง่าย ใช้บนมือถือ/แท็บเล็ตได้ (responsive)
- **NFR-7 ภาษา** — ภาษาไทยเป็นหลัก (เตรียมโครงสร้างรองรับหลายภาษาได้ในอนาคต)
- **NFR-8 Audit** — บันทึกเวลาเมื่อกรรมการ submit/แก้ไขคะแนน เพื่อการตรวจสอบย้อนหลัง

## 5. 📐 สมมติฐานและขอบเขต (Assumptions & Out of Scope)

**สมมติฐาน (ยืนยันแล้ว)**
- น้ำหนักหัวข้อรวมกัน = **100% เป๊ะ** (ระบบ validate ก่อนเปิดแข่ง ไม่ normalize ให้)
- คะแนนเต็มต่อหัวข้อคือ 5 คงที่ทั้งระบบ (แต่ละหัวข้อต่างกันที่น้ำหนัก ไม่ต่างที่คะแนนเต็ม)
- **คะแนนที่กรรมการให้ = จำนวนเต็ม 0–5** (score_step = 1); คะแนนสุดท้าย (ถ่วงน้ำหนัก+เฉลี่ย) แสดงทศนิยม 2 ตำแหน่ง
- **Admin ใช้บัญชีเดียว** (ทำงานทีละคน — ยังไม่ต้องรองรับหลายบัญชีในเวอร์ชันแรก)
- จำนวนกรรมการทราบก่อนเริ่มแข่ง; จำนวนผู้เข้าแข่งขันปรับเพิ่ม/ลดได้ก่อนและระหว่างแข่ง
- 1 การแข่งขัน = 1 ชุดหัวข้อ/น้ำหนัก (ยังไม่รองรับหลายรอบ/หลายสายในเวอร์ชันแรก)

**Out of scope (เวอร์ชันแรก)**
- ระบบหลายรอบ/หลายสาย (multi-round / brackets)
- การให้คะแนนแบบตัดคะแนนสูงสุด-ต่ำสุด (ใช้เฉลี่ยธรรมดาก่อน — เพิ่มภายหลังได้)
- การแสดงผลขึ้นจอใหญ่แบบ live (ทำภายหลัง)
- ระบบสมาชิก/บัญชีผู้ใช้เต็มรูปแบบสำหรับกรรมการ

## 6. ❓ คำถามที่ยังเปิดอยู่ (Open Questions)

- **OQ-1 (รอยืนยัน user จริง)** วิธี tie-break เมื่อคะแนนสุดท้ายเท่ากัน — แนวทางที่ตกลงเบื้องต้น: เทียบคะแนนเฉลี่ยในหัวข้อที่มีน้ำหนักสูงสุดก่อน ถ้ายังเท่าให้ครองอันดับร่วม
  > สถานะ: เจ้าของโปรเจกต์จะนำไปถาม user จริงอีกครั้งเพื่อยืนยัน

- ~~OQ-4 real-time dashboard~~ → **ยืนยันใช้** — Admin มี Live Dashboard เห็นสถานะสด (ไม่เห็นคะแนน) ระหว่าง present สด (ดู `04-live-workflow.md`)
